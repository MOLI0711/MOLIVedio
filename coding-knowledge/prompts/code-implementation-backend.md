# 代码实现阶段（后端）
## 核心目标
按照任务清单逐个实现后端代码，遵循技术方案和编码规范。
## 交互流程
### 准备工作
**在开始编码前，先完成以下准备**：
1. 读取 `task.md`（任务清单）
2. 读取 `design.md`（技术方案）
3. 了解当前 Phase 和任务列表
---
### 逐任务实现（循环执行）
⚠️ **一次只实现一个任务，完成后等用户确认再继续**
#### 开始任务
**告知内容**：
- 当前任务编号和描述（如：T1.1 创建 user 表）
- 当前 Phase 进度（如：Phase 1 - 数据层，共 3 个任务，当前第 1 个）
---
#### 实现代码
**实现内容**（根据任务类型）：
**数据库任务**：
- 创建数据库迁移脚本（Flyway/Liquibase）
- 添加索引、外键
- 数据迁移 SQL
**逻辑层任务**：
- Service 层：业务逻辑实现
- Repository 层：数据访问层
- 事务管理、异常处理
**接口层任务**：
- Controller：接口定义、参数校验
- DTO：请求/响应对象
- 错误码定义
**缓存任务**：
- 缓存 Key 设计
- 缓存更新逻辑
- 缓存失效处理
**遵循原则**：
- 严格按照 `design.md` 中的设计实现
- 遵循项目编码规范
- 考虑异常情况和边界条件
- 添加必要的日志和注释
---

### 检查点验证
**在每个 Phase 结束时**：
- 总结本 Phase 完成的任务

---
## 代码质量要求
### 编码规范
- 遵循项目现有的代码风格（命名、格式、注释）
- 类/方法命名清晰表达意图
- 避免魔法数字，使用常量
### 异常处理
- 捕获预期异常，记录日志
- 定义明确的错误码和错误信息
- 避免吞异常
### 日志埋点
- 关键操作记录 INFO 日志
- 异常情况记录 ERROR 日志
- 包含必要的上下文信息（用户 ID、订单 ID 等）
### 数据库操作
- 避免 N+1 查询
- 合理使用索引
- 考虑事务边界
- 大批量操作考虑分页
### 接口设计
- 参数校验完整
- 响应结构统一
- 错误码清晰
- 考虑幂等性
### 测试
- 为核心逻辑添加单元测试
- 覆盖正常流程和异常情况
- 集成测试验证接口
---
## 任务类型参考
### Feature 开发
1. 先改接口/DTO 定义
2. 再实现 Service 层逻辑
3. 补充 Repository 层
4. 最后补测试
### Bugfix
1. 先理解问题根因
2. 加复现用例/回归用例
3. 修复问题
4. 验证修复有效
### Refactor
1. 小步迁移
2. 保持行为一致
3. 加对照测试
